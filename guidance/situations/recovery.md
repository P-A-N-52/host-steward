# 中断、记录损坏与恢复

状态损坏时保留原文件，停止新维护，不静默重建基线。`current.json` 损坏会阻断 patrol/status/resolve 以及需要目录摘要的文件调查；inventory 只读查询和不依赖 current 的服务调查仍可用于核对事实，但不能据此绕过维护停止。先保留原件并在工作副本上定位 JSON 或字段错误，对照可信备份、其他状态与实际对象判断能否恢复语义；无法确认时由负责人恢复可信备份，不删除原件或重新 init 覆盖。修复候选先经只读查询验证，再恢复巡检与维护。`current.json` 与 `operations.json` 由统一 reader 校验已知容器和直接索引字段；缺失的新 v1 字段可兼容，错误类型、重复 key/ID、非有限数字和坏 quarantine 身份均 fail closed。旧基线缺 scope 的显式升级不等于自动修复损坏状态。未知 current 顶层保留，未知 operation kind 只作不可执行、不可淘汰的历史证据。

状态、约定、资源定义和目录说明使用有界普通文件读取：拒绝链接、FIFO、目录和设备，超限或读取中元数据变化时停止。锁文件也必须为普通文件；锁占用时本轮退出，不删除正在使用的锁文件。非阻塞打开用于避免 FIFO 等待，不保证普通磁盘 I/O 的硬超时。

host 缺失不表示可以重置已有状态。`init` 只接受空目录（普通 `.lock` 除外），先预检所有 payload，host 最后提交；正常失败只尝试清理本次创建且身份／内容仍匹配的文件和本次空目录，不递归、不清锁、不删变更内容。若 host 无法确认或移除，保留其余已完整内容并报告残留，不能宣称 initialized；物理 I/O 故障下不保证零残留。先备份、核对残留并恢复受信约定；只有确认回滚完成且目录仅剩锁文件时才可重试 init。状态区不作为普通维护或 restore 目标，旧版本误移动的状态文件也不能靠放宽托管路径保护自动恢复。

操作证据在 `operations.json`。planned/failed/restoring 表示需要观察实际源与目标后判断；quarantined 表示已验证移入回收区且保留恢复依据。先逐条核对实际对象，能按现有 restore 安全续作的才续作，其余保留证据并由负责人决定后续恢复或迁移；不要直接重放旧命令。目录身份或文件身份变化时停止。当前 demo 没有通用 abandon/reconcile CLI，planned/failed 等未终结证据不自动淘汰；达到 operation_records 预算会阻止后续操作写入，不能为腾空间手工挑选删除或假装已经收敛。

```sh
./steward restore --state /本机状态 --operation 操作编号
```

恢复默认预览；本机约定仍允许且原位置为空时可 `--apply`。restoring 记录可在源与目标身份精确匹配时显式续作；若源已恢复而回收副本已删除，只收敛记录。原位置被新对象复用时拒绝覆盖。恢复后核对身份、大小、修改时间与源目标位置。操作目录清理结果单独报告；非空或权限失败不否定已验证的文件恢复，也不递归删除额外内容。回收区应由本机约定所有者控制；身份复查不是针对恶意并发写入者的原子条件删除保证。

状态容量不足时先查看普通记录、现存未完成操作及预算，不能为了腾空间丢弃恢复证据。工具在文件变更前预留记录空间；达到上限时停止新增。命令在锁内刷新当前约定，patrol 提交前和维护副作用前做语义复核；约定变化时旧计划不提交，planned/restoring 证据保留且不使用旧预算二次写状态。该 demo 没有自动修复损坏状态或自动续跑未完成维护的能力。
