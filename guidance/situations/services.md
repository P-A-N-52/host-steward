# 服务与后台任务异常

先核对稳定身份、常驻约定、实际配置和相关时间线。观测清单中的服务标签不等于健康；需要用所属程序的只读健康检查或实际功能确认。

查看服务观测的 scope：macOS demo 查询当前 launchd 域，Linux 查询 systemd 系统管理器；其他管理域未覆盖，不能把未出现在当前列表中的对象判为停止或不存在。程序相对路径结合启动配置的 WorkingDirectory 核对，定时或按需启动的任务没有当前 PID 也不能直接判为遗留。

获取有限近期错误，关联配置变化、资源压力、重启时间与依赖。不要直接打印环境变量、认证配置或完整进程参数。

疑似遗留服务先按 [inventory](../inventory.md) 读回档案并使用 inspect 调查启动配置、主 PID 和 roots 内的字面引用，结合已有调用线索与项目迁移记录核对用途和依赖。描述仍写旧项目、长期低占用或没有近期请求都只能作为线索；备用和按需服务也可能空闲。工具仅查当前用户或系统范围、主 PID 的可见端点，不覆盖其他用户、子进程或历史调用，不能据此报告已确认孤儿。

macOS 程序相对路径与工作目录、定时及按需启动的区别见 [launchd 官方说明](https://github.com/apple-oss-distributions/launchd/blob/main/man/launchd.plist.5)；Linux 使用 show 的有效属性并区分 --user/--system，见 [systemctl 官方手册](https://github.com/systemd/systemd/blob/main/man/systemctl.xml)。磁盘配置与管理器生效状态可能不同，应分别报告。

调查结果固定展示目标身份、已查、未查、证据时间、发现的引用、拟议动作影响与待决定事项；未查项决定能否继续操作，应与结论一起显示。静态配置、当前连接和一段调用记录各有覆盖边界，不合并成“无人依赖”的保证。

定时任务另查调度时区、实际运行环境、调用分支与动作记录。任务退出成功不证明维护分支运行或成功，吞掉异常的脚本尤其需要核对目标结果。精确分钟条件遇到延迟可能漏过；改变时区是否改变执行时间、是否漏跑应分别验证。回环监听只证明观察时未直接监听外部地址，转发与代理未查时保留缺口。

确认退役后分开列出停止、禁用、移除程序和移除数据的影响与权限；批准其中一项不自动包括其他项。共享服务先核对其他用户和 agent 的依赖。

恢复动作只能来自已有约定：确定目标、影响、维护窗口、回退与功能验证。demo 仅提供观察，不实现自动重启、安装或配置修改。没有对应授权时登记原因与所需决定；保护对象高占用仍可调查，但不自动停止。
