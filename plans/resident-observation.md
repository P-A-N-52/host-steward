## 目标与边界

将资源采样、文件观察和统计保存从单轮 patrol 中拆出，由常驻组件持续推进。人和 agent 通过统一 CLI 查询当前事实、历史摘要、变化与采集缺口；agent 根据用途、依赖与实际证据决定调查、维护和通知。

查询目标沿用 charter.md、design.md 及现有指导中的设计指标，当前重点是明确配置怎样控制采集范围、采集深度、频率、成本与历史保留，以及这些设置怎样反映在结果中。

- Linux 先落地，macOS 后续适配。实现沿用 Python 3.9+ 标准库约束。
- host.json 继续作为每台主机的约定、授权与预算来源；运行时观测和进度保存在状态中。
- 观察范围与维护授权各有含义，纳入观察不自动授予修改权限。
- 先形成一个可独立验证的资源采集闭环，再推进文件基线与原生事件。

## 配置方案与跨平台路径

2026-10-24 讨论确认采用可配置的目录范围、逐 root 深度与排除规则，并明确考虑 Linux／macOS 的路径差异。以下结构作为后续实现依据，尚未进入运行代码；默认值和新配置版本号在实现时确定。

### 每台主机一份配置

继续使用本机 host.json。roots 从路径列表调整为对象列表，每个 root 保存路径、最大采集深度和排除设置。采样频率、历史保留和资源预算也由该配置控制；采集状态只记录实际生效范围和配置版本证据。

下面是 Linux 主机的结构示例，不是可以直接覆盖现有 host.json 的完整配置；路径在接管时按实际主机填写：

```json
{
  "roots": [
    {
      "path": "/home/pan/projects",
      "max_depth": 3,
      "exclude_names": [".git", "__pycache__"],
      "exclude_paths": ["build/cache"]
    },
    {
      "path": "/var/log",
      "max_depth": 0,
      "exclude_names": [],
      "exclude_paths": []
    }
  ]
}
```

### 路径在目标主机上确定

- 配置结构共用，具体路径按主机保存。同一个项目在 Linux 上可能位于 /home/pan/projects，在 macOS 上可能位于 /Users/pan/projects；示例不能作为所有主机的默认位置，也不通过替换 /home 与 /Users 来迁移配置。
- 初始化或配置编辑入口在目标主机上核对用户指定路径，并将规范绝对路径写入配置。用户目录、卷挂载位置、服务配置及状态目录按实际环境取得，不能根据操作系统名称或用户名拼出路径。
- 运行配置中的 path 使用已经确认的绝对路径，不依赖启动时的工作目录、环境变量或波浪号展开。交互配置入口若支持这些简写，应在目标主机展开并展示结果后保存；远程部署不能用控制端 Mac 的路径规则替 Linux 解析，系统服务启动后也不能把服务账户的主目录当作被管理用户的主目录。
- exclude_paths 相对于所属 root，按路径分量匹配指定文件或子树；不得越出 root。exclude_names 按单层名称在各层匹配。路径包含空格或中文时作为普通路径值处理，不拼成 shell 命令。
- 解析、包含关系和重叠检查集中使用目标平台的路径与文件系统接口。保留文件名原有大小写与 Unicode 表示，不统一转小写或自行改写名称；同一对象的不同路径别名按实际文件系统核对，不能仅靠字符串前缀判定包含关系。
- 沿用 root 规范化、状态目录排除、子目录符号链接不跟随、仅扫描 root 所在卷和 root 不重叠的基本边界。路径别名在配置时展示其实际目标；其他卷需要单独登记 root。路径不存在、暂时未挂载或无法访问时记录原始原因与未覆盖范围，不能自动改用其他目录或创建监控目标。
- 本机路径及对象身份与主机、卷共同解释；把配置用于另一台主机时重新确认路径并建立基线，不沿用原主机的目录身份与采集进度。

### 采集深度、展示深度与执行预算

根目录为第 0 级，max_depth 为非负整数。max_depth 为 0 时检查根目录的直属条目，不进入子目录；为 3 时进入到第三级目录，检查这些目录的直属文件。更深目录可作为边界条目记录，但不遍历其内容，也不把未采集子树的体积计入总量。

采集深度决定实际覆盖范围；展示深度只控制 CLI 展开到哪一级。若需要整个目录树的体积但只展示三级，就需要覆盖完整子树，并在查询时限制展示层级。是否提供显式的全深度取值，在字段实现时确定，仍受每批执行和状态容量预算约束。

| 设置 | 含义 | 到达边界后的行为 |
| --- | --- | --- |
| root、max_depth、排除项 | 用户选择的观察范围 | 范围外不采集，结果明确标示边界及体积口径 |
| 每批时间、条目与运行资源预算 | 当前批次允许的工作量 | 保存进度，后续继续，未完成范围保持可见 |
| 查询展示层级与输出预算 | 本次返回多少内容 | 限制展开和分页，不改变后台采集范围 |

按配置扫完可标为该范围完整；实际范围仍随结果返回。调整当前“达到深度上限即扫描不完整”的语义，避免主动选择浅层观察后持续产生覆盖故障。范围以内未完成、采集失败与范围之外分别报告。

### 配置生效与历史连续性

完整校验后在采集批次边界切换配置，查询能够读回实际生效范围及版本。旧配置启动的批次不能冒充新配置的结果；受范围变更影响的候选扫描与事件监听一并更新。无效配置保留原始错误并暂停受影响采集，历史仍可读且标明时间，不显示为已成功应用。

- 增加目录或加深层级：补建覆盖并显示建立进度，不能马上宣称新范围完整。
- 移除目录或缩小层级：停止相关扫描和监听，退出当前观察视图，旧记录按历史保留，不解释为文件删除。
- 修改排除规则或实际路径目标：核对受影响范围；范围不可比时报告比较缺口，暂停直接计算普通删除、体积差和增长率。

迁移现有 roots、exclude_names、limits.scan_depth 时显式转换并核对旧语义，特别核对深度边界和目录规则引用。新旧格式按版本区分，不同时充当活动规则来源。

## 数据、调度与存储

- 各类指标使用其明确口径：累计计数器按实际时间求差，内存保存当前值及必要统计，目录保存基线和变化。进程／主机重启、身份复用、计数器重置和断采不能被拼接成连续序列。
- 高频历史采用追加、局部更新和淘汰接口；查询按对象与时间范围读取，避免反复重写完整历史列表。
- 采集进度与已确认结果分别保存，不能把未完成候选快照作为完整基线。
- 采集函数继续抛出原始异常。调度层如何隔离独立任务的失败、记录错误与最后成功时间，需要在实现前明确；影响共同存储的问题应停止受影响写入。
- 划清观测、档案、待办和操作证据的事务边界，避免后台提交旧快照覆盖其他写者的新结果。
- 先设计短事务与查询路径，再以实机并发查询决定日志模式。若采用 WAL，容量和备份必须覆盖其伴随文件与检查点行为。
- 采样频率、并发、索引规模及保留策略依据 CPU、内存、存储、电源和前台负载实测确定；整个状态区与临时空间都计入成本。

验证使用实际主机、正式 CLI 和真实对象，记录操作、原始返回、耗时与独立读回；历史测试代码用于查阅案例。长时间稳定性、压力和迁移结果在实际完成后记录，不能用短时演示代替。

配置与路径验收包括：在 Linux 与 macOS 分别使用本机真实路径，检查不同主目录／挂载位置、带空格和中文的路径、大小写或路径别名、相对排除项及相似前缀目录；验证深度 0 和多级目录边界、配置增减深度、卷离线、运行中修改配置与服务重启。按平台分别记录结果；仅在 Linux 通过的检查不算 macOS 已验证。

已有 Netdata 资料位于 references/field-netdata-k6-2026-10-23/README.md。该资料记录 2026-10-23 的短时 Linux 实测，可用于制定对照项目；不表示当前主机状态或长期结果已经重新验证。正式切换前先核对现场。
