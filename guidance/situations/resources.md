# 常驻程序与资源异常

先查常驻约定，再查程序身份与任务。`pid + started + executable` 用于比较进程生命周期；启动时间变化后不沿用旧趋势。服务标签存在只证明被观察到，不证明功能正常。

CPU 看任务进展、持续时间和对主要工作的影响，demo 的 ps 百分比不是瞬时整机利用率。内存看相同生命周期的多次样本及实际压力，缓存和一次高占用不直接证明泄漏。工具只对至少四次、跨十分钟且持续增长的有限 RSS 样本提出调查线索；未确认泄漏，不能据此杀进程。

识别本轮采样命令与短时前台任务，避免把观察自身造成的占用当成遗留负载；不能按 bash 等解释器名称排除所有同类进程。指标保留来源、单位、时间口径与可用性，单位不明或与任务条件明显矛盾时标为未验证，不据此计算功耗费用或作处置结论。

GPU 在本 demo 中标为未知，不调用需要提权的功耗采样。存储同时看目录增量和卷可用空间，父子目录统计存在重叠。模型费用没有配置来源时同样标为未知。

先降低 Steward 自己的非必要开销。需要恢复服务或调整其他程序时，确认本机允许动作、维护窗口和验证方式；demo 没有停止进程的命令。调查无法证明原因时保存有限证据与待核验事项，不反复试错。
