# Host Steward 0.2

**面向 AI 助手的主机长期维护 skill：整理文件、照看程序与运行环境，记住资源的用途、归属和保留理由，让每一轮工作接着上一轮继续。**

以 [MIT 许可证](LICENSE)发布，支持 macOS 和 Linux，只依赖 Python 3.9+ 标准库。

## 使用方式

把项目地址和你的需求一起发给 AI 助手，例如：

```text
https://github.com/P-A-N-52/host-steward

请使用 Host Steward 帮我长期管理这台电脑上的文件和相关运行环境。
先读取 SKILL.md，按入口说明准备运行内容，和我确认管理范围，从只读盘点开始。
```

## 为什么我们要做这个 skill

日常工作和生活会积累文档、照片、下载资料和备份；AI 助手执行任务时，也会留下脚本、临时目录和运行环境。时间一长，有些还在使用，有些需要长期保留，有些已经可以收尾，只看名字很难分清。

我们希望助手能把这些资源的来龙去脉记下来：知道为什么创建、谁在用、什么时候该收尾。这样，后续整理有据可查，重要资料也能得到妥善保留。

## 设计思路

项目分为三个部分：

- **指导**：告诉助手如何接管、巡检，以及遇到问题时如何判断。
- **工具**：负责观察变化、调查资源、执行维护和验证结果。
- **状态**：保存这台主机的管理约定、资源知识和处理记录，供下一轮继续使用。

先弄清用途和依赖，再决定如何维护。日常工作在用户约定和资源预算内安静完成，需要用户取舍时再说明具体问题。

动态状态保存在每台主机独立的 `steward.sqlite3` 中，本机约定 `host.json` 和指导保留为可直接审阅的文件。已有 JSON 状态通过显式迁移接入；迁移、查询导出和数据库备份见[首次接管](guidance/setup.md#旧状态迁移与导出)。

需要例行核对的本机健康脚本可以在 `host.json` 的 `custom_checks` 中登记，由 `steward.py check` 按显式授权、在时间和输出预算内直接执行，不经过 shell；结果不自动写入状态，`patrol` 也不会隐式运行。配置与脚本契约见[自定义检查](guidance/situations/custom-checks.md)。

## 项目结构

AI 实际使用的目录：

```text
host-steward/
├── SKILL.md    助手入口
├── guidance/   接管、巡检与专项指导
├── tools/      由本地 agent 调用的 Python 工具
└── state/      本机约定与资源定义模板
```

项目目标见 [charter.md](charter.md)，设计细节与当前实现范围见 [design.md](design.md)。
