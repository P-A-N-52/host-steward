# 首次接管

确认主机主要用途、观察根目录、常驻程序与保护对象。整机资源观测和目录覆盖分别报告：demo 不默认递归扫描 `/`，需要用 `--root` 明确目录。

首次接管默认只读，先交付空间地图与待确认事项。除大小外，核对目录归属、用途、关联服务或项目、重建条件、保留理由、支持的维护方法及证据时间；外部 agent 的报告是线索。按 [inventory](inventory.md) 登记重要资源的长期知识，区分来源陈述与现场观测；档案不自动证实用途、依赖或处置许可。

验证后续轮次能从明确路径读回关键规则与知识；独立进程读回与新 agent 会话自动加载分别验证，前者不证明后者。检索需区分关键词与语义通道、故障、未覆盖和没有匹配；语义不可用或查询返回空结果不能推断没有历史。agent 转述的建议保留作者与待确认状态，容量和期限阈值不能自行变成删除许可。

```sh
./steward init --state /绝对路径/本机状态 --root /绝对路径/观察目录 --purpose '主机主要用途'
./steward patrol --state /绝对路径/本机状态
```

`init` 仅用于新建或空状态目录（普通 `.lock` 除外）。已有 inventory、current、operations 或本机指导时，即使 host 缺失也拒绝覆盖；先保留证据并按 [recovery](situations/recovery.md) 恢复。初始化先预检完整内容和容量，host 最后提交；清理失败的残留不能当成已初始化，也不能直接覆盖重试。

本机约定只有 `host.json` 一份。初始目录维护约定和常驻清单为空；观测到程序不自动获得清理权限。常驻条目使用 executable 与 reason；具体目录规则使用 path、purpose、kind（cold/temporary/active/service）。每个规范 path 只能有一条规则，相同或冲突的重复项均拒绝；不同路径嵌套仍选择最具体规则。allow_notes、allow_quarantine 默认缺省为不允许。状态目录及其内容始终不作为 note/quarantine/restore 的托管目标。

桌面、其他用户或 agent 的工作区、共享缓存与模型分别确认范围，不能由“共用文件系统”推导管理权。用户可授权边界明确的日常动作；未另行约定的最终删除逐项预览并确认。当前 demo 没有最终删除命令，也不验证人工批准的来源；`--apply` 只表达执行意图。

允许写说明或回收的目录还需保存 directory_id。先运行 `./steward status --state /本机状态 --path /约定目录`，在 `directory_index` 中找到 path 与规则目录完全相同的行，取其 `id`，格式为 `dev:ino`；没有精确行时先补齐观测，不能拿父目录身份或猜测值代替。临时目录回收需有 retention_days 和 recycle_bytes 容量上限，按修改时间执行既有期限；这只适用于用户已指定的临时内容，不是通用文件价值判断。工具不自动判定任务结束或文件依赖，执行者需先核对这些事实。

接管先观察用途不明的自定义目录。用途确认后登记规则，再用 note 预览说明。已有 `AGENTS.md` 保留原文，仅更新 Steward 标记区；只读接管时不使用 `--apply`。

初始预算取自 skill 的 `state/host.example.json`，部署后的实际预算只以本机状态目录的 `host.json.limits` 为准。状态总容量包含替换临时文件。根据真实规模调整前先核对开销；达到预算会报告缺口或拒绝写入，不要直接提高预算来掩盖重复记录。

`init --root` 将显式输入归一后保存；后续编辑 `host.json` 的 roots 和目录规则需使用无符号链接的规范绝对路径，不在验证时隐式迁移授权。

初期本机指导保留所有通用说明，`adaptation.json` 记录版本和裁剪情况；后续依据真实主机裁剪。skill 源指导更新不会自动替换已有状态区副本，升级时需对照改动复核本机指导，不静默覆盖。工具尚未验证的平台能力不得写成已经可用。
