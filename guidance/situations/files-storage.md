# 文件、目录体积与收纳

默认按目录看新增、消失、移动、修改及体积差；目录新增/删除不展开所有子项。文件内容不自动读取，变化来自元数据比较。部分扫描、离线根目录和对象身份变化都属于缺口，不能当作删除证据。同路径 ID、类型或 birth 不连续时记录 `identity_changed` 修改与身份缺口，目录换代不展开子项，身份连续的跨边界移动仍单独保留；换代净体积差保留但标为 `continuity_gap`，不用于普通增长速率或增长待办。可靠移动跨越目录边界时，该目录及受影响祖先标为 `migration_delta`，迁入增量不当作普通增长；包含移动两端的共同祖先仍可报告真实净增长，预算合并时按实际汇总范围计算，不把重叠子树体积混入根目录净值。只有两侧 birth 可取得且相同时才确认为 moved；birth 缺失的跨路径同 ID 只保留端点变化和 `move uncertain`，不强行配对。

macOS 优先读取系统 FSEvents 线索，随后有界快照复核；事件历史有效且所有 roots 快照完整时才推进已提交游标，暂时失败保留旧位置，连续 3 次无法提交后显式失效并重建，失效位置不会复用。Linux demo 没有常驻监听，快照之间的中间事件不可追溯。状态保存当前完整基线，扫描不完整时不覆盖它。`coverage_complete` 仅指元数据快照覆盖，不代表中间事件完整。当前版不支持跨轮续扫海量目录，也不保证跨 roots 的移动配对。

比较前核对 `coverage_scope`：每个 root 的过滤项、状态排除路径、深度、根设备及跨卷边界决定是否可比。scope 改变或旧基线缺少 scope 时显式报告缺口、重建基线，不产生该轮普通删除、体积差或增长待办。跨卷边界只展示有界样例与截断标志；当前范围完整不代表排除卷已检查。已退役 root 的活动基线移除，重新纳入时新建；旧变化仍是历史、待办仍需显式关闭。状态目录及其后代不能作为说明、回收或恢复目标。

先查本机目录规则、用途与依赖依据，再更新占用。记录空间结论时包含测量时间与口径；文件夹名不能证明缓存可重建，未发现引用也不能证明模型可删。配置、使用者或目录身份变化时复核相关结论，避免每轮重新猜测，也避免沿用失效知识。

日志暴增时先看目录增长、写入来源、任务与有限样本，再判断重复报错、重试循环或日志设置。不要复制整份巨型日志。生产程序的轮转与修复需按本机约定使用现有工具，本 demo 只提示问题。

收纳规则：服务数据原位维护；活跃项目留在工作区；重要冷资料长期保护；明确临时内容在既有期限、依赖确认后才进入待回收区。未知用途原位调查。移动到同卷回收区不释放空间。

备份按来源与恢复用途分组；“最近 3 份 + 每月 1 份”须同时明确月度归档期限、容量、固定恢复点与恢复依赖，保留集合取并集。规则未确认或恢复能力未经验证时只列建议。demo 不计算或执行备份淘汰。

备份检查区分格式可解析、数据库内部完整性、备份组配套与业务恢复。副本检查通过不证明最初备份完整或当前版本可恢复；原件前后哈希一致只说明本轮未改变其字节，不能替代恢复演练。

缓存优先使用软件支持的接口；可重建条件、共享使用者与权限须现场确认，uv 缓存不直接删目录，参见[官方说明](https://docs.astral.sh/uv/concepts/cache/)。SQLite WAL 按数据库状态保护，不能当普通 log 删除或隔离，参见 [SQLite 文档](https://www.sqlite.org/wal.html)。回收站缺少原路径等元数据只说明恢复线索不足，不代表可清空。

自定义收纳目录内应有简短 `AGENTS.md`，包含用途、保留类别、规则来源和本机索引入口。调用 note 时使用本机规则，先预览；已有用户原文保留，Steward 只更新 `host-steward:begin/end` 区域。每份说明最多 8 KiB，不追加每轮变化或秘密。

```sh
./steward note --state /本机状态 --path /约定目录
./steward quarantine --state /本机状态 --path /约定临时文件
```

预览符合既有授权后可加 `--apply`。最终删除不在 demo 能力中。程序正在使用或归属不明的文件不能仅依据年龄回收。
